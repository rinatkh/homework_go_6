## Как не потеряться в конкурентности

Не пытайся писать весь раздел сразу. В конкурентном коде ошибка часто выглядит не как обычное неверное число, а как зависание, гонка данных или горутина, которая не может завершиться.

Работай по одной функции:

1. Прочитай её описание в `docs/task.md`.
2. Нарисуй словами: кто запускает горутину, кто ждёт, кто владеет каналом и кто может остановить работу.
3. Реализуй только одну функцию.
4. Запусти тесты текущего раздела.
5. После блока с общей памятью обязательно запусти `make test-race`.

Внутри каждого раздела сначала реши задачи 1–3 — они закрепляют основной механизм. Затем переходи к задачам 4–5: они повторяют тот же принцип в новом контексте и помогают проверить, что решение не было запомнено только для одного примера.

## Важно

- Не меняй сигнатуры функций и не редактируй тесты.
- Не используй `time.Sleep` для ожидания завершения горутины.
- Вызывай `WaitGroup.Add` до запуска горутины, а `Done` — через `defer` внутри неё.
- Общие изменяемые данные защищай одним и тем же Mutex и при записи, и при чтении.
- Канал закрывает отправитель, который точно знает, что новых значений не будет.
- Не закрывай канал со стороны получателя и не отправляй значение после `close`.
- Помни границу буфера: отправка `capacity + 1` ждёт, пока чтение не освободит место.
- Не путай закрытый и nil-канал: закрытый канал после чтения всех значений возвращает `ok == false`, операции с nil-каналом ждут навсегда.
- `range` читает один канал до `close`; `select` ждёт одну из нескольких операций.
- Если в `select` есть `default`, он не ждёт: при отсутствии готовых `case` сразу выполняется `default`.
- Не используй `len(ch)` как механизм синхронизации: это только снимок состояния.
- `context.Context` передавай первым аргументом; не сохраняй его в структуре и не передавай `nil`.
- Проверяй ошибки context через `errors.Is(err, context.Canceled)` и `errors.Is(err, context.DeadlineExceeded)`.
- В функции с параметрами типов выбирай минимальное ограничение: `any`, если операции над значениями не нужны; `comparable`, если используешь `==`, `!=` или ключи `map`.
- Не заменяй параметры типов на `any` с последующей проверкой типа во время выполнения: это убирает полезную проверку компилятором.
